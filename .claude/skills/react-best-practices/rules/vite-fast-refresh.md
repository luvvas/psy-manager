## Keep Component Files Fast-Refresh Friendly

React Fast Refresh only hot-swaps a module when it exports nothing but components. Mixing components with constants, helpers or hooks in the same file forces a full reload and loses state. The lint rule `react-refresh/only-export-components` enforces this.

**Incorrect:**

```tsx
// patient-form.tsx
export const patientSchema = z.object({ ... })   // non-component export
export function formatCpf(v: string) { ... }      // non-component export
export default () => <form>...</form>             // anonymous component

// router.tsx
function PageLoader() { ... }                      // component in a non-component module
export const router = createBrowserRouter([...])
```

**Correct:**

```tsx
// schema.ts
export const patientSchema = z.object({ ... })

// patient-form.tsx
export function PatientForm() { ... }

// components/page-loader.tsx
export function PageLoader() { ... }
```

- Named function components; no `export default () =>`.
- Schemas, constants and helpers in `types.ts`, `schema.ts` or `utils.ts` next to the feature (or `src/utils/format.ts`).
- No side effects at the top level of component files.
- Unexpected full reloads usually mean a circular import or a path with the wrong case (`vite --debug hmr`).

Existing exceptions: files generated by shadcn in `components/ui/` (e.g. `buttonVariants` in `button.tsx`) — leave them as generated.
